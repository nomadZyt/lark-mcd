# 群投票拼单和 AA 台账

一场拼单只对应一家店、一个时段，最多 10 份。成员在卡片上改自己的份数，这一步调用麦当劳接口 0 次。只有 `OWNER_OPEN_ID` 可以截止、核价和确认下单。确认走原来的演练模式和守卫。付款链接只私发给发起人。机器人不收款，AA 只记账。

时段写在投票卡上，用来记住这场约定的取餐时间。核价和下单按到店即时单处理，不把这个时间传给预约参数。

## 飞书权限

在个人测试租户的企业自建应用里，只加这些和群拼单、台账有关的权限：

| 权限 | 用途 |
| --- | --- |
| `im:message.group_at_msg:readonly` | 接收群里 @ 机器人的消息 |
| `base:record:create` | 新增多维表格记录 |
| `base:record:update` | 发起人刷新订单后，更新支付状态 |

如果开放平台把这两项收成旧版的 `bitable:app`（查看、评论、编辑和管理多维表格），开通这一个即可。不要再额外开通删除记录或读取全部多维表格的权限。

不要开通「获取群组中所有消息」（`im:message.group_msg`），也不要开通通讯录全量。私聊、发消息、更新卡片用的权限见 [README](../README.md)。

事件仍是 `im.message.receive_v1`，回调仍是新版 `card.action.trigger`。机器人默认只收到群里 @ 它的消息。

## 建多维表格

在个人测试租户里新建一张多维表格，数据表使用下面的字段名和类型。单选的选项需要事先建好，否则飞书写入会失败，程序会改记到本机 JSON。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| 日期时间 | 日期 | 下单时间，北京时间 |
| 门店 | 文本 | 门店名 |
| 订单号（后 4 位） | 文本 | 只有后 4 位。演练模式写「演练」 |
| 场景 / 事由 | 单选 | 午餐、加班餐、团队活动、其他 |
| 人数 | 数字 | 参与分摊的人数 |
| 参与人 | 人员 | 投票时的 open_id |
| 餐品明细 | 文本 | 这个人选的餐品 |
| 应摊金额（元） | 数字 | 整数分换算后的元 |
| 订单实付（元） | 数字 | 核价或订单实付 |
| 支付状态 | 单选 | 未下单、待支付、已支付，以及接口返回的状态原文 |
| 是否已开票 | 复选框 | 程序只写入未勾选。开票请到麦当劳 App 的订单页 |
| 已结算 | 复选框 | 程序只写入未勾选。线下结算后自己勾 |

把应用加为这张表的协作者，权限选可编辑。打开表格，地址类似：

```text
https://example.feishu.cn/base/bascnXXXXXXXX?table=tblXXXXXXXX
```

`bascnXXXXXXXX` 是 `BITABLE_APP_TOKEN`，`tblXXXXXXXX` 是 `BITABLE_TABLE_ID`。写进本机 `.env`，不要提交。

```bash
BITABLE_APP_TOKEN=
BITABLE_TABLE_ID=
```

两个都留空时，台账写到 `~/.lark-mcd/ledger.json`。表格接口失败时也写这个文件。本机另外有一个 `ledger-index.json`，只记订单号后 4 位、open_id 和多维表格的 record id，用来更新支付状态，不记手机号、地址、取餐码和完整订单号。

## 在个人测试租户里试一遍

1. 按 README 把长连接跑起来。`MCD_MODE=mock` 可以用演示菜单；要真实核价再改 `MCD_MODE=real`，并保持 `DRY_RUN=true`。
2. 用 Token 主人的账号私聊机器人：`/麦麦 门店 城市 关键词`，点一家门店保存。
3. 建一个测试群，把机器人和另外一两个测试账号拉进来。
4. 在群里 @机器人，发送 `/麦麦 拼单 午饭 12:00`。
5. 其他账号在卡片上点加号。群里的卡片会更新份数。这一步的麦当劳请求次数是 0。
6. 换一个非主人账号点「截止并核价」或「确认下单（发起人）」。应当只看到提示「只有发起人可以核价和下单」。
7. 主人点「截止并核价」。卡片出现合计和每人应摊。可以改事由和取餐方式。
8. 主人点「确认下单（发起人）」。
   - `DRY_RUN=true`：群里写明没有下单。主人的私聊里是将要提交的内容。台账订单号是「演练」，支付状态是「未下单」。
   - `DRY_RUN=false`：才会调用 `create-order`。付款链接只出现在主人的私聊。群卡片写「已下单，待发起人付款」，不出现付款链接。
9. 主人付款后，在群卡片或私聊里点刷新。群里可以出现取餐码。台账只更新支付状态，不写取餐码。

分摊规则：金额用「分」做整数。同一餐品按份数拆开原始小计，订单优惠、餐具费和实付差额按这个小计的比例分摊。除不尽的那几分由发起人承担。每个人应摊金额加起来等于这笔订单的实付。

## 本地不用飞书也能看

```bash
npm test
npm run demo
```

`npm run demo` 的后半段会打印投票卡、成员勾选、非发起人被拒绝、发起人核价、群卡片和发起人私聊分开、本机台账，以及第 11 份被拒绝。演示不连接麦当劳，也不连接飞书。
